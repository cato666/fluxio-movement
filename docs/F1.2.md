## Modelo afectado

Migración `0002_f12_athlete_analysis`, sucesora de `0001_f1_persistence`: en `analyses` añade `exercise VARCHAR(100)`, `load_kg FLOAT`, `objective TEXT`, `analysis_json_path TEXT`, todas nullable para preservar filas F1.1. Añade check de carga no negativa y finita; amplía check de estado con `PENDING`. Las rutas `analysis_json_path` históricas se rellenan desde el ID del análisis completado. Mantiene `result JSONB`, rutas de video, FK al atleta y las repeticiones normalizadas. El `downgrade` convierte filas PENDING a FAILED para poder restaurar la restricción previa; úsalo solo cuando corresponda.

Los nuevos envíos validan ejercicio, objetivo, formato, nombre y carga antes de crear una fila. El procesamiento registra PENDING, luego PROCESSING, y finalmente COMPLETED con resultado/repeticiones atómicos o FAILED con error técnico. El análisis antiguo sin metadata se muestra como «Análisis anterior».

## Problemas encontrados y deuda técnica

- El primer pase tuvo un error de sintaxis en un test; se corrigió. Otro test enviaba carga opcional vacía como cadena, mientras el formulario real la omite; se corrigió el fixture. La suite final pasó.
- Sin autenticación: identidad fija Gastón Demo y URLs de video públicas. No publicar la demo como servicio multiusuario real.
- Solicitud síncrona y sin límite de tamaño; puede haber timeout para clips largos.
- Una caída del proceso puede dejar estados PENDING/PROCESSING. Falta recuperación y reintento automático.
- PostgreSQL y filesystem no son transaccionales entre sí; pueden quedar archivos huérfanos. Se requieren backups coordinados.
- Archivos anteriores sin fila de base siguen sin importarse automáticamente.
- Los campos nuevos son nullable en la base para migración no destructiva; la API obliga ejercicio y objetivo. Una futura restricción requiere backfill de registros históricos.
- Se conserva la coexistencia de paquetes OpenCV heredada de F1.1.

**Detención:** F1.3 no iniciada; requiere autorización del usuario.
